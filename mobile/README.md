# Kids Islam

Android-first, offline learning application built with React Native, Expo SDK 57, TypeScript, Expo Router, SQLite, SecureStore, Zustand, and `expo-audio`. This directory is independent of the existing Vite web classroom in the repository root.

## Run on Android

Use Node.js 22.13 or newer. Install Android Studio with its SDK and create an emulator, or connect an Android device with USB debugging enabled.

```sh
cd mobile
npm ci
npm run android
```

For a Windows native build, place the checkout at a physically short path such as `C:\ki`. Drive aliases can produce inconsistent paths in native autolinking. In PowerShell, configure the SDK and Android Studio Java runtime if they are not already set:

```powershell
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
$env:Path = "$env:ANDROID_HOME\platform-tools;$env:Path"
```

Use the actual installation paths if Android Studio or the SDK is installed elsewhere. The local verification used Java 21 and Android SDK 36. Cloud builds through the `preview` or `production` EAS profile avoid local Windows native path limits.

`npm run android` builds and installs a native development binary. To use Expo Go for basic module development instead, run `npm start`. Background audio and Android permission acceptance must use a native binary:

```sh
npx expo run:android
```

First launch asks the parent to create a six-digit PIN. Add a child nickname, choose learning settings, then enter Kids Mode. Profiles and progress use the device database; no email account is required. Development educational content is deliberately disabled until the parent enables the review pack. Canonical seeded Quran text is available independently of that switch.

## Production build

```sh
cd mobile
npm ci
npm run lint
npm run typecheck
npm test
npm run export:android
npx eas-cli@latest build --platform android --profile production
```

The last command requires an Expo account and Android signing setup. `eas.json` builds an Android App Bundle for production and an APK for the `preview` profile. No store submission is performed by these commands. Validate the release on real Android hardware before distribution. The JavaScript export is not an installed APK or evidence of native device acceptance.

## Credentials and network consent

Copy `.env.example` to a local `.env` only if configuring a proxy. `EXPO_PUBLIC_CONTENT_PROXY_URL` is a public URL, not a credential. Parent network consent defaults to off. No child analytics, ads, public profiles, social chat, location, microphone, or camera feature is included in the mobile app.

Quran Foundation production access requires `QF_CLIENT_ID` and `QF_CLIENT_SECRET` on the server. Sunnah access requires `SUNNAH_API_KEY` on the server. See `server/README.md` and its environment example. Never prefix a secret with `EXPO_PUBLIC_`, put it in `app.json`, or commit `.env`. API keys are never accepted in child UI.

## Quran sources and offline data

The chapter directory contains all 114 chapters. Five initial surahs are seeded from attributed, permitted sources: Al-Fatihah, Al-Ikhlas, Al-Falaq, An-Nas, and Al-Ma’un. Source text and translations are not generated by AI. See `src/content/fixtures/quran-SOURCES.md` for exact origin, permissions and retained notices. Available features depend on the source: missing transliteration, tafsir, timing or word audio is shown as unavailable rather than invented.

The Quran provider abstraction separates canonical source records from display. Quran Foundation offline copies must use Content Sync, including snapshots, deletes and final checkpoint handling. They must not be built from ordinary API responses. Environment-specific resource versions, last sync, tokens and download states are stored locally. Production `quran_core:1` is required for the complete canonical resource; prelive has a limited dataset. The app only syncs when a parent permits network access. Review API terms and refresh requirements before production deployment.

The 29 seeded ayahs include unchanged Alafasy recordings (about 2.7 MiB) from Islamic Network / Al Quran Cloud under the publisher’s educational redistribution terms. Checksums and source URLs are retained in the audio manifest. These play without network access. Additional recitations use synced metadata and parent-approved downloads with size estimates. The app never synthesizes Quran recitation. Local recordings remain usable offline.

## Local database

`kids-islam.db` uses SQLite with foreign keys and a versioned migration. Required tables include profiles, lessons, per-child progress, surahs, ayahs, Quran resources/checkpoints, hadith source records and educational lessons, duas, quiz questions/attempts, memorization, bookmarks, downloads, settings and sources. Child deletion cascades to the child’s progress. Parent settings are local. PIN hashes and lockout settings are stored in SecureStore rather than SQLite.

Canonical Arabic is stored as returned by the provider. Do not normalize, tokenize/rejoin, strip diacritics, insert verse numbers into the source string, or globally flip screen direction. Arabic display blocks use RTL; English blocks use LTR. Tests cover exact source round trips.

The shared SQLite adapter queues queries and transactions so unrelated work cannot join a transaction or be rolled back with it. Inside `withTransactionAsync`, use the callback's scoped database handle for every query. Quran repositories share one initialization task per connection and retry after a failed seed. Concurrent loading, progress saving and rollback isolation have regression tests.

## Lessons and content review

The development catalog includes five Arabic lessons, three Hadith teaching excerpts, five Duas, Five Pillars, Wudu steps, Salah introduction, and two Prophet story structures. The wider topic catalogs provide expansion points; they do not claim that full lessons for every Prophet/topic have been authored.

Add sourced religious records in their provider/fixture files and original educational explanations in `src/content/lessons/`. Keep narrator, source reference, grade (only when supplied), attribution, version, verification date, license, and reviewer metadata. Do not copy copyrighted children’s commentary or invent citations, Prophetic dialogue, rulings, translations, or events. Published educational content requires qualified review. Draft, needs-review and approved-but-unpublished explanations are unavailable in normal child mode. Parent-enabled review mode clearly labels them.

Parent Mode → Content review provides a persistent editor for original teaching text and discussion. Source Arabic, translations, references, quizzes, and pack restrictions remain read-only. Saving an edit creates a new version and revokes earlier approval. The review workflow records a named reviewer's attestation and exact version before allowing publication. This records review evidence; it does not independently verify a person's qualifications. Development-only fixtures retain that restriction even after local review. Load separately reviewed production packs with `developmentOnly: false` to publish them for normal child mode.

Arabic tracing saves participation/completion, not handwriting correctness. Memorization uses Listen → Read → Repeat → Hide → Recite → Complete and a child’s own Easy/Need Practice/Practice Again rating. No recitation accuracy or emotion recognition is claimed. English educational narration is separate from sourced Quran recordings.

## Parent controls and accessibility

PIN-protected routes cover children, settings, source information, downloads, content review, reset/delete and PIN changes. Entering Kids Mode, backgrounding the app, or reaching the two-minute parent-session timeout locks parent access. PINs have a random salt, PBKDF2-SHA256 derivation, and a five-attempt lockout. This is an app boundary, not an operating-system kiosk; Android screen pinning instructions appear in Parent Mode. A rooted or compromised device is outside this boundary. Losing a PIN requires local app data recovery/reset; there is no cloud recovery account.

Large touch targets, screen reader labels, high contrast text, adjustable Arabic sizes and a static interface avoid motion dependence. No child view exposes clickable external links. Network access is optional and parent-controlled. Lesson progress is retained after closing the app. A parent can reset one child without deleting another child’s work.

## Verification

```sh
npm run lint
npm run typecheck
npm test
npm run export:android
```

Automated tests exercise real SQLite migrations and profile isolation, reopening storage, progress, provider mapping, sync, immutable Arabic, review gates, PIN derivation/lockout, RTL block direction, quiz scoring, audio state and repeat behavior, and bundled recording checksums. Live API tests require credentials. Exercise native first-install flows with the parent-enabled development pack or properly published content. Quiz attempt summaries retain actual scores; individual selected answers are not retained.

The implementation check on October 7, 2026 passed lint, TypeScript and all 65 automated tests. The Android Hermes export includes all 29 recitation recordings. Weekly progress uses an append-only practice history so repeating a lesson does not erase earlier activity.

A test-signed native release APK (ARM64 and x86_64) built successfully and passed all twenty fresh-install acceptance steps on the Pixel_6 Android 13/API 33 emulator. The run covered a new PIN/profile, offline Quran reading and attributed translation, recitation, six-stage memorization, Arabic tracing and a 100% quiz, a Hadith lesson and a 100% quiz, Dua practice, parent access and progress after force-stop/relaunch. All six saved lesson records, scores and attempt counts were identical after reopening. Native playback, pause, repetition, next-ayah advance and active media playback with the screen off were observed. The emulator had audio output disabled, so physical-device listening quality and accessibility checks remain pending. The finished APK manifest contains no camera, microphone or location permissions. Both GitHub Actions workflows passed on the implementation commit.

On Windows, keep the native build checkout in a short path. A deeply nested checkout caused CMake/Ninja path-length failures in React Native dependencies during verification. The generated `android/` and `ios/` directories are ignored; native configuration belongs in `app.json` and config plugins.

`npm audit` on October 7, 2026 reports 28 findings (18 high, 10 moderate) in SDK-managed dependencies and transitive tooling, including braces and node-forge. Suggested automatic remediation would downgrade Expo or break its supported dependency set. Do not treat a passing build as a security release approval; resolve or assess these findings against supported upstream fixes and rerun the audit before distribution.
